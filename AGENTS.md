# Lesson design

Assume learners are very new to networking and software. Apply this to every lesson, including new ones.

- Under the title, explain the real-world situation, what the learner controls, what they should do first, and what success means. Name the objects being handled (for example, customer purchase orders) and explain any initial failure or outage.
- Define technical terms in plain language where they are introduced. Explain how the visual metaphor corresponds to software and what actions such as accepted, queued, saved, and delivered actually mean.
- Distinguish lesson parts from goals within a part. Label the current part, the number of parts, and which goals belong to it.
- Show numeric progress and explicit pending, in-progress, and complete states for every goal. Count only the actual server-defined goal; unrelated actions must not appear to satisfy it.
- Keep instructions, contextual hints, visual feedback, and code connected. On desktop, learners must be able to read code while seeing and operating the visual. Reveal hints next to their trigger.
- Preserve keyboard access, reduced-motion support, and a usable narrow-screen layout.
- Reveal the lesson progressively: one short explanation and one next action at a time. Keep full goal details, definitions, logs, and code optional until the learner requests them.
- Make route changes explicit with a labeled control, plain-language choices, and a visible selected route. Do not rely on tiny buttons embedded in artwork.
- Give code a substantial reading area with readable type while keeping the factory operable alongside it. Place code and restart controls in the lesson workspace, not the global header.
- Give the opening scenario and objective primary visual importance. Let learners read the introduction before revealing the interactive workspace.
- Remove decorative microcopy, repeated metadata, always-on connection labels, and empty counters. Show operational status on the component it describes, and show an error only when there is a problem.
- Keep the default workspace focused on the factory and current action. Put progress, contextual help, definitions, and request history behind clearly named tools; open one tool at a time. Show counts in the current step only when they help the learner act.
